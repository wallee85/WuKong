## 1. 总览：整条流水线

```
参考图（三视图）
   ↓ ①  图生 3D（混元）
高模 + 贴图（49.5 万面）
   ↓ ②  清理（焊接、归一化、去多余几何）
干净的高模
   ↓ ③  减面 / LOD
18k / 8k / 3.5k 三档
   ↓ ④  搭骨架（23 根骨骼）
   ↓ ⑤  蒙皮（自动权重）
   ↓ ⑥  动画（idle 循环）
   ↓ ⑦  导出 GLB
Godot 导入 → 挂武器 → 水墨后处理
```

**核心观念：这七步里，只有第 ① 步是“AI 生成”，其余全是传统 3D 管线。** AI 给的是原材料，不是成品。

---

## 2. 阶段 ①：准备参考图

### 为什么必须是“三视图 + 同一姿势”

图生 3D 模型靠**多张不同角度的图**推断厚度和背面。如果正面是 T-pose、侧面是手臂下垂，模型会收到矛盾信息，生成出“半抬手”的畸形。

我们用的三张（`front.png` / `side.png` / `back.png`）：

- **正交投影**：没有透视变形，远处和近处一样大。手机拍的照片有透视，不能直接当建模参考；
- **同一姿势**：都是手臂自然下垂、握拳；
- **同一比例**：人物高度都缩放到 1800 px，脚底对齐；
- **纯白背景**：去掉原图的纸张纹理，避免被当成模型的一部分。

> 术语：**正交（Orthographic）** 就是“平行投影”，游戏里的三视图、工程图都用它。Blender 的正交相机就是干这个的。

### T-pose 与 A-pose

- **T-pose**：双臂水平，像字母 T。绑骨工具最喜欢，左右完全对称；
- **A-pose**：双臂自然下垂约 45°，像字母 A。建模时肩部、衣服褶皱更自然。

这次生成用的是 A-pose（手臂下垂），因为三视图本来就是那个姿势；T-pose 图留作绑骨参考，**不能混着喂**。

## 3. 阶段 ②：混元 3D 图生 3D

### 输入

- 网页版：3D 生成 V3.1，选「多张图片」，传 `front`（正图，必填）、`side`（左图）、`back`（背图），其余留空；
- 模型面数选 **500k**（选项里 1.5m/1m 太重，50k 太粗）；
- 提示词描述角色 + 要求“写实 PBR、干净反照率、无手绘笔触”。

### 为什么提示词要强调“写实 PBR”

水墨效果我们打算在 Godot 里用**后处理**做。如果贴图本身已经是水墨笔触，再叠墨线和纸纹就会脏、会花。所以资产阶段要“干净写实”，风格留到最后一步。

### 输出

- 60.7 MB 的 GLB；
- **495,126 个三角面**、337k 顶点；
- **3 张 4096×4096 贴图**：BaseColor（颜色）、Metallic-Roughness（金属度/粗糙度）、Normal（法线）；
- 姿势是 A-pose，朝向 -Y，身高 1.118 m（生成器不按真实单位）。

## 5. 阶段 ④：清理

### 5.1 焊接（Merge by Distance）

刚导入时模型有 **7487 个碎片**。不是模型碎了，而是**UV 接缝处的顶点被复制了一份**（每个贴图块是独立patch）。直接绑骨会在接缝处裂开。

做法：全选顶点 → 按距离合并（0.3 mm）。结果：

- 337,281 顶点 → 247,269；
- 7487 个碎片 → **1 个整体**。

### 5.2 归一化尺寸

把高度缩放到 **1.895 m**，脚底落到 z=0，左右居中。之后所有部件（衣服、武器、动画）都用同一把尺子。

### 5.3 处理多余的尾巴（第一版）

第一版生成时传了背图，而背图里尾巴在角色右侧、正图里在左侧，模型就**左右各做了一条**。试过按坐标切、缩进身体、按贴图颜色删，都会连带破坏裙摆——因为 50 万面的融合网格里尾巴和裙子是长在一起的。

最终改成**只传正图 + 左图、不传背图**（背面让模型推断）。第二版生成出来就只有一条尾巴，问题从源头消失，不再需要动刀。

> 代价：背面的贴图是推断出来的，精细度略低于正面；尾巴根部也略微有点歪。对游戏资产可接受。

## 6. 阶段 ⑤：LOD（多细节层次）

### 为什么要 LOD

手机 GPU 吃不消 49.5 万面。做法是准备几个不同精度的版本，游戏里按距离切换：

| 版本 | 面数 | 用在哪 |
|---|---|---|
| LOD0 | 18,000 | 近景（对话、展示） |
| LOD1 | 8,000 | 中距离 |
| LOD2 | 3,500 | 远处/小怪 |

### 怎么减

用 Blender 的 **Decimate（减面）** 修改器，模式 Collapse：它会把不重要的边合并，尽量保住轮廓。UV 会跟着保留，所以贴图不用重做。

> 注意：这是“自动减面”，不是“重拓扑（Retopo）”。自动减面的布线很乱，近看有线框问题；真正商业级资产要手工重拓扑。我们现在是**原型级**。

---

## 7. 阶段 ⑥：骨架

### 骨架是什么

骨骼（Armature）是一组有父子关系的“棍子”，蒙皮后模型的顶点会跟着骨骼动。游戏角色的骨架通常按人体结构命名，方便动画重定向。

这次一共 **27 根**：

| 部位 | 骨骼 |
|---|---|
| 中轴 | `root` → `pelvis` → `spine_01` → `spine_02` → `chest` → `neck` → `head` |
| 左臂 | `clavicle_l` → `upperarm_l` → `lowerarm_l` → `hand_l` |
| 右臂 | `clavicle_r` → `upperarm_r` → `lowerarm_r` → `hand_r` |
| 左腿 | `thigh_l` → `shin_l` → `foot_l` → `toe_l` |
| 右腿 | `thigh_r` → `shin_r` → `foot_r` → `toe_r` |
| 尾巴 | `tail_01` → `tail_02` → `tail_03` → `tail_04` |
| 武器 | `weapon_r`（挂在右手，不参与蒙皮） |

### 关键设计

- **`weapon_r` 是挂点骨**：金箍棒以后作为独立模型挂在这根骨头上，换武器不用改角色；
- **命名跟 Godot 对齐**：Godot 4 的 `SkeletonProfileHumanoid` 认这套命名，动画可以重定向到其他角色；
- **root 在原点**：方便游戏里做位移和根运动。

## 8. 阶段 ⑦：蒙皮（Skinning）

### 自动权重

Blender 的 `ARMATURE_AUTO`（自动权重）会计算每根骨头对每个顶点的影响，用的是“热量扩散”算法。

- 每个顶点最多受 **4 根骨骼**影响（游戏引擎的标准上限）；
- 权重会自动归一化（加起来 = 1）；
- 肩膀、腋下、髋部是重点检查区。

### 怎么验证

摆一个夸张姿势（比如双臂抬平），看：

- 腋下有没有撕裂/穿插；
- 袖子有没有跟着走；
- 膝盖弯曲时裤腿是否塌陷。

我们测了 T-pose：肩部和袖子变形正常，没有明显破面。

> 自动权重不是万能的。手指、面部、裙摆这些地方，商业项目都要手工刷权重。

---

## 9. 阶段 ⑧：动画

### idle 循环

- 61 帧 @ 30 fps ≈ 2 秒；
- 骨盆轻微起伏、胸腔呼吸、头部微动、手臂微摆；
- **第 61 帧和第 1 帧完全一样**，这样循环播放不会跳。

### 为什么用关键帧而不是脚本生成

动画的本质就是“在时间轴上记录骨骼的旋转/位移”。关键帧 + 插值是最直接的方式，游戏引擎也认这种数据。

## 10. 阶段 ⑨：导出到 Godot

### 导出设置

- 格式 **glTF 2.0 Binary（.glb）**；
- 勾选蒙皮（Skins）和动画（Animations）；
- 只导出 LOD0 + 骨架（LOD1/2 留在 .blend 里，需要时单独导出）。

### Godot 里怎么用

1. 把 `.glb` 拖进项目，Godot 自动生成场景；
2. 场景里会有 `Skeleton3D` + `MeshInstance3D` + `AnimationPlayer`；
3. 用 `AnimationTree` 做状态机（idle → walk → attack）；
4. 金箍棒做成独立场景，用 `BoneAttachment3D` 挂到 `weapon_r` 骨骼上；
5. 水墨效果：`CompositorEffect`（桌面）或全屏 shader + 深度纹理（移动端）。

> 45 MB 主要是那三张 4K 贴图。移动端建议后期烘成 2K 图集，能降到 10 MB 以内。

## 11. 阶段 ⑩：水墨后处理（已实现）

**资产保持写实，风格在引擎里加**：`assets/shaders/ink_post.gdshader` 挂在 CanvasLayer 的 ColorRect 上，读屏幕纹理做后处理。

实现的内容：

1. **墨线**：对屏幕亮度做横向/纵向差分，超过阈值的地方压成墨色（`edge_threshold` / `edge_strength`）；
2. **宣纸纹理**：叠加 `assets/textures/paper.png`，按 `paper_strength` 混合；
3. **降饱和 + 提对比**：`desaturate` 控制保留多少固有色；
4. 参数都在 shader 里，可以直接在检查器的 ShaderMaterial 上调。

运行后按 **K** 切换开关。关掉后处理就是正常写实角色，方便做 LOD、调试和换风格。

> 这是**屏幕空间**方案：只根据最终画面算墨线，不依赖深度/法线缓冲，移动端也能跑。代价是线条会“贴”在画面上，不做随距离变化的粗细；要更高级的效果可以后面换 `CompositorEffect`（仅桌面）。

## 12. 已知问题（诚实清单）

| 问题 | 影响 | 下一步 |
|---|---|---|
| 尾巴根部略歪 | 近看造型不够顺 | 微调根部顶点 |
| UV 是生成器给的，密度不均 | 贴图局部拉伸 | 重展 UV + 烘 2K 图集 |
| 毛发是几何尖刺 | 近看粗糙、面数浪费 | 换 hair cards |

| 贴图带少量烘焙光照 | 重新打光时略脏 | 重烘 albedo |
| 没有表情/口型 | 不能做对话 | 加 blendshape |

**当前定位：可跑、可看、可绑的原型资产**，不是可以直接上线的商业成品。

## 13. 术语表

| 术语 | 解释 |
|---|---|
| 拓扑（Topology） | 模型表面的布线方式，决定变形好坏 |
| 重拓扑（Retopo） | 在模型表面重新画一套干净布线 |
| UV | 把 3D 表面“展开”成 2D 贴图坐标 |
| 蒙皮（Skinning） | 让顶点跟随骨骼运动 |
| 权重（Weight） | 某根骨骼对某个顶点的影响大小 |
| LOD | 不同精度的模型，按距离切换 |
| PBR | 基于物理的材质（颜色/粗糙度/金属度/法线） |
| glTF / GLB | 一种开放的 3D 传输格式，Godot 原生支持 |
| T-pose / A-pose | 绑骨/建模用的标准站立姿势 |
| 正交投影 | 无透视的平行投影 |

## 14. 脚本清单（每一步都留了脚本）
